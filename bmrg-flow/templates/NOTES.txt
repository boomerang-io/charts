** Starting **
service-core migrates the database before it serves anything. Follow it with:

  kubectl rollout status --namespace {{ .Release.Namespace }} deployment/{{ include "flow.core.serviceName" . }}

A v3 database can take minutes; the startup probe allows {{ mul $values.core.startupProbe.periodSeconds $values.core.startupProbe.failureThreshold }} seconds.

** Sign-in **
{{- if $values.global.auth.enabled }}
Proxy mode: the authenticating proxy at {{ $values.global.auth.serviceName }}{{ if $values.global.auth.namespace }}.{{ $values.global.auth.namespace }}{{ end }} guards the web app.
{{- else }}
OIDC is configured in Settings > Auth (issuer and client id); until both are set, sign-in is proxy mode
and expects an authenticating proxy in front of the web app (global.auth).
{{- end }}

** Activation **
On an empty database the first person to sign in activates the instance and becomes its admin by
entering the activation code. It works once; after activation it is inert.

  kubectl get secret --namespace {{ .Release.Namespace }} {{ include "flow.secretName" . }} -o jsonpath="{.data.FLOW_ACTIVATION_CODE}" | base64 --decode

** Service token **
The bootstrap token (also the dispatcher's credential) is in the Secret:

  kubectl get secret --namespace {{ .Release.Namespace }} {{ include "flow.secretName" . }} -o jsonpath="{.data.FLOW_BOOTSTRAP_TOKEN}" | base64 --decode
